# 최종 가치 평가 요약

기준일: 2026-11-09. 대상: `pathcosmos/korean-dense-llm`의 데이터 처리 소스(수집·정제·중복 제거·분할·토큰화·출처/배포·학습 입력). 가중치는 기술 품질 0.4, 오픈소스·포트폴리오 0.3, 재사용성 0.3. 상세 근거는 [README.md](README.md), [IMPROVEMENTS.md](IMPROVEMENTS.md), [t1/RESULTS.md](t1/RESULTS.md).

## 한 줄 결론

**오픈소스·포트폴리오 자산으로서의 가치는 "중간 이상"이고, 그 가치는 정제 알고리즘이 아니라 재현성·계약·분할·출처 추적에 있다. 이 데이터 처리가 모델 품질을 높이는지는 평가할 수 없다.**

## 계층별 점수 (1–5, 임시)

| 계층 | 기술 품질 | 포트폴리오 | 재사용성 | 가중 합 |
|---|---:|---:|---:|---:|
| 정제·PII | 2.3 | 3.0 | 3.7 | 2.9 |
| 중복 제거·분할 | 4 | 4 | 2 | 3.4 |
| 토큰화·로더 | 4 | 4 | 2 | 3.4 |
| 수집·출처·계약·배포 | 3.5 | 3 | 2 | 2.9 |

- 점수는 평가자 판단이고 계층 간 교정되지 않았다. 소수점 차이에는 의미를 두지 말 것. 평가 후 새 근거는 방향과 신뢰도만 갱신했고 점수를 다시 매기지 않았다.
- "측정 불가" 항목은 0점이 아니라 점수에서 뺐다.

## 강점 (근거 있음)

- **견고성·재현성**: 크래시 재개, 변조 거부, sha 계약 체인이 테스트로 뒷받침된다. 클린 클론에서 clean→dedup→split→tokenize 코어가 문서대로 동작했고 재개·거부 로직도 실제 데이터에서 확인했다. CI와 같은 조건(Python 3.12, 새 환경, 새 클론)에서 344 passed / 42 skipped / 0 failed.
- **누수 방지 분할과 교차 소스 exact 중복 제거**, 합성/실제 분모를 분리 보고하는 측정 철학.
- **한계를 숨기지 않는 문서화.**

## 약점 (근거 있음)

- **정제 알고리즘은 차별점이 아니다.** FineWeb-2를 이미 통과한 데이터 위에서 `check_ko`가 더 지우는 문서는 3.7%이고 그중 약 69%가 `short`, 24%가 `dup_lines`다. FW2 미경유 소스에서는 FW2식 기준보다 훨씬 관대하다(HPLT 7.7% vs 30.1%, wiki 29.7% vs 53.5%).
- **의미적 저품질 문서를 규칙으로 거의 못 잡는다.** 라벨 100건의 의미적 저품질 27건 중 `check_ko` 3건, FW2 필터 10건(대가로 정상 문서 7/67 거절). 싼 구조 신호로도 약하다(최고 AUC 0.70, 정상 90% 유지 시 27건 중 7건).
- **PII 규칙이 얇다**(전화·이메일·주민번호 정규식 3개). 소스별로 가치가 다르다: FineWeb-2는 이미 익명화되어 실제 이메일이 0.08%, HPLT는 11.5%.
- **이식성 결함이 남아 있다**: 문서 진입점 불일치, `prepare_source_manifest.py` 소스 하드코딩, 실제 승인 사슬의 증거 파일 부재. 데이터 텍스트 재배포 권리 판단의 최신 기록이 저장소에 없다(적법성 판단은 이 평가 범위 밖).

## 이번 평가에서 소스를 고친 것

| 변경 | 효과 |
|---|---|
| `clean.py` 출력 서명 | 입력·정책이 바뀐 낡은 결과를 조용히 재사용하던 위험 제거 |
| `filters.py` 정책 객체(기본 동작은 바이트 동일) | 임계값 실험 가능, 골든 오라클로 고정 |
| 옵트인 PII 정책 3종 | 실제 샘플에서 URL 속 13자리 기사 ID 주민번호 오탐 제거 |
| 코드 루트/데이터 루트 분리 | 클린 클론에서 막히던 감사·토크나이저가 통과 |
| FW2식 품질 필터 옵트인 | 켜면 의미적 저품질 10/27 포착. 단 약 330배 느림(9 vs 3,000 docs/s) |
| 측정 하네스 `dataqa/` | gold 라벨, 군집 통계, 사전 검수 도구 |

## 측정으로 우선순위가 낮아진 것

- NFD 한글로 인한 거절: 0 / 159,965문서. 특수 토큰 문자열: 한국어 web·wiki 0/159,965, 코드 0/276,625 (수학·영어는 미측정).

## 증거의 질

| 항목 | 상태 |
|---|---|
| 라벨 100건 | 50건 JUN 구두 확인(reject 33 + keep 17), 50건은 에이전트 라벨 + 독립 검수자 2명 일치(사람은 보지 않음). 소스당 n=20~40 |
| 에이전트 검수 | 같은 모델 계열이라 일치는 약한 증거. κ=1.0은 겹침 10건의 값이라 신뢰도 증거가 아님 |
| 사전 검수 후보 6건 | JUN이 전부 원래 라벨 유지(교정 0/6) → "사전 라벨이 keep으로 기운다"는 방향 신호는 철회 |
| 통계 | 군집(row group) 표집, 표본 샤드 기준. 샤드 선택이 원 파이프라인과 같은지는 **불확실** |
| FW2 비교 | 인자를 원본 소스와 대조했고 일부 단계(언어 ID·추출·MinHash·step 6)는 제외. FW2가 쓴 datatrove 버전은 **불확실** |

## 평가할 수 없는 것

1. **효용(모델 성능)**: 같은 모델·시드로 데이터 변형만 바꿔 학습하는 ablation(T2)이 필요하다. GPU가 없는 이 환경에서는 못 한다. 소규모 모델에서 한국어 벤치마크가 무작위보다 유의하게 나오는지도 확인하지 못했다.
2. 1.29억 문서 규모의 성능·신뢰성(과거 실험 JSON만 있음, 재현 못 함).
3. arXiv 한국어 CommonCrawl 필터링 논문과의 비교(접속 불가).
4. 사업·수익화 가치(가중치에 포함하지 않음).

## 열린 결정과 다음 단계

| 항목 | 담당 | 비고 |
|---|---|---|
| FW2식 필터를 켤지 | JUN | 정상 문서 10% 손실 대가로 의미적 저품질 37% 감소가 학습에 이득인지는 T2로만 확인 |
| 옵트인 PII 정책 채택 | JUN | 채택하면 새 출력 트리에서 재정제 |
| wiki 토막글(<200자, wiki 27.8%) 정책 | JUN | 라벨이 아니라 정책 결정 |
| 이름·주소·사업자번호를 PII로 볼지 | JUN | 정책 미결 |
| 데이터 텍스트 재배포 권리 기록 | JUN | 저장소에 최신 기록 없음 |
| 문서 진입점 정정, `release/files.json` 재생성 | 다음 릴리스 | 릴리스 문서의 해시 검증과 충돌해 이번에는 미수정 |
| split 거대 연결 컴포넌트 게이트, near-dup 반영 | 개발 | 합성에서만 재현. 실제 규모 측정이 먼저 |
| 학습 ablation(T2) | GPU 환경 | 효용에 답하는 유일한 방법 |

## 용도별 판단

- **오픈소스·포트폴리오 자산**: 충분히 평가됨. 위 약점(차별성, 이식성, 권리 기록)을 문서에 정직하게 쓰면 신뢰도가 오른다.
- **재사용 가능한 부품 모음**: `filters.py`와 계약 프리미티브는 추출 가능. 나머지는 `common/data_contracts` 결합이 강하다.
- **"이 데이터 처리가 모델을 낫게 하는가"**: 답할 수 없다. T2 없이 결론을 내리지 말 것.
